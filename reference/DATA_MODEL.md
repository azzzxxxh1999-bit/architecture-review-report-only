# `modules.json` — the state / source of truth

One file per project. The Markdown report is a pure projection of it (regenerated by
`render.py`); never hand-edit the outputs. Hand-edit only decomposition/structural fields
in `modules.json`. Scan facts and audit facts use their owning scripts and the validated
atomic state repository; then re-render.

## Field ownership

| Field | Written by | When |
|---|---|---|
| `meta.*`, `bands`, `spine`, `coupling`, `deps`, `desc`, `paths`, `label`, `id`, `band` | **model** (decomposition) | `init`, and when structure changes |
| `loc`, `contentHash`, `meta.tracked_*` | `scan.py --write` through `AuditStateRepository` | every scan |
| `score`, `grade`, `tags`, `findings`, `auditedHash/At/Rev` | `apply_audit.py` through shared `AuditContract` + `AuditStateRepository` (from an **auditor subagent**); never hand-edit | each (re)audit |
| `tests` | **test-author subagent** | `test`, and the baseline step of `fix` |
| `lastFix` | **model** (after the acceptance gate) | each `fix` |
| `reportThemes` | **model** (synthesis) | after a full/partial audit |
| `architectureDimensions` | **auditor/model synthesis**, evidence-backed | full audit; affected dimensions on incremental audit |
| `architectureLenses` | **model summary only**; status/score are re-derived by `render.py` | after dimension results change |
| `schemaVersion`, `semanticValidation`, `auditVersion`, `auditDelta` | **`version.py` only** | successful publish; working reports may leave version metadata absent/null |

Test files are **excluded from a module's audit scope** by default (so editing a test
does not mark the module stale and test LoC does not inflate the production-code score).
The `tests` field records them separately as the regression net.

## Maintainability gate projection (read-only)

`maintainability_gate.py` does not write `modules.json`. It joins canonical audit facts,
the active immutable manifest, the effective `maintainabilityClaims` standard, and
repository safeguard evidence into a transient result:

```jsonc
{
  "claim": "scoped | project",
  "passed": false,
  "status": "SCOPED_PASSED | SCOPED_REWORK_REQUIRED | PROJECT_MAINTAINABLE | PROJECT_REWORK_REQUIRED",
  "projectClaimAllowed": false,
  "auditVersion": "audit-v0016",
  "evaluatedModules": ["module_id"],
  "criticalModules": ["core_or_spine_id"],
  "failureCount": 1,
  "failures": [{"code":"FULL_AUDIT_REQUIRED", "message":"…"}]
}
```

Field ownership remains unchanged: auditors own scores/findings, `version.py` owns
retained mode and validation gates, the repository owns Git/CI configuration, and the
gate script owns only the derived claim. Never persist a hand-authored passing status.

## Four lenses and eight dimensions

The report uses four beginner-facing lenses, but the state retains all eight professional
results. The mapping is fixed and exhaustive:

| Lens | Dimension ids |
|---|---|
| `split` / 分 | `responsibility`, `boundary` |
| `connect` / 连 | `contract`, `dependency` |
| `change` / 变 | `data_logic`, `composition_state`, `evolution` |
| `protect` / 保 | `safeguards` |

`render.py` supplies the labels/questions from the canonical definitions and derives each
lens's status with `risk > warning > unknown > good`. A lens score is emitted only when
every owned dimension has a valid score; otherwise it is `null`. This prevents an
unreviewed dimension from being averaged into a false pass.

Every `risk` or `warning` dimension must contain at least one evidence item. Evidence
should include a stable `id`, a plain-language `description`, and the most precise current
location available (`file`, `symbol`, `line`, `moduleId`). Every `relatedModules` id must
exist in `modules`. If evidence is unavailable or tooling cannot decide, use
`status: "unknown"` and `score: null`.

## Staleness

A module is **stale** when `contentHash != auditedHash` (its code changed since last
audit), **unaudited** when it has no `score`/`auditedHash`, **empty** when its `paths`
match no files (likely deleted → drop it or fix the globs). `scan.py` reports these.
Stale and unaudited modules always need a fresh subagent; a module may also need
re-audit when a changed public contract, dependency, or persistence boundary affects it
even if its own content hash is unchanged.

## Coupling vs score

`coupling` (low/med/high/core) is a **structural** property — how central the module is
(degree + role). `score` is a **quality** property — how clean the code is. They are
independent: a `core` module can be clean (A) and a `low` leaf can be broken (F).

## Custom audit standard (`standard.json`)

The scoring standard is data, not code: `reference/standard.json` holds the rubric,
severities, coupling levels, and the issue `tags` (each `{id,label,labelZh,bad,en,zh}`).
A project overrides it at `<project>/.codemap/modules.json`'s sibling
`standard.json`. Audits must use the project standard's tags when present — including custom ones.

## Retained audit versions

`<project>/.codemap/modules.json` remains the mutable current working state. Completed
website and game audits are retained separately under
`<project>/.codemap/versions/audit-vNNNN/` so later source changes cannot rewrite prior
evidence.

Each current-contract retained version contains a manifest, the audited `modules.json`,
rendered Markdown, the effective standard/config, a deterministic source
snapshot, a delta against the previous version, and `semantic-receipt.json`. The receipt
binds the semantic contract, effective standard, canonical audit state, source snapshot,
gates, scope, baseline and mode by fingerprints. `scripts/version.py` is the only writer that assigns a
version number, promotes the staged directory, maintains `versions/index.json`, and
verifies both artifact integrity and retained meaning. It stamps
`schemaVersion`/`semanticValidation`/`auditVersion`/`auditDelta` into the staged state and
regenerates the Markdown report from that exact state before any
promotion, so the retained page cannot disagree with its JSON. `index.json` keeps both
the chronological `latestVersion` and the selected working-view `activeVersion`; a
rollback changes only `activeVersion` and the mutable working artifacts, never history.
The first version is `full`; subsequent
versions are `incremental` or `expanded_incremental` according to the changed architecture
scope. A no-delta run does not create an empty version. A retained v1 directory without
a receipt is independently validated as read-only `legacy-contract`; it is never silently
upgraded or rewritten.
